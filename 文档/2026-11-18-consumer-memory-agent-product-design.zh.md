# Agent Note: Consumer product surfaces for memory and agents

Status: proposed

[English](2026-11-18-consumer-memory-agent-product-design.md) | 中文

## Problem

Web UI 至今仍是一个带侧边栏的聊天框。面向 C 端用户的两个能力都没有被界面解释清楚：一个是静默召回、静默写入的记忆引擎，另一个是会规划、派生子代理、调用工具、可能请求批准的执行体。[ui-memory](../代码文件/packages/client/ui-memory/README.md) 的面板能显示最近一次召回和记忆库，但前提是用户知道要去打开它，而且对话里没有内联的召回痕迹。模型的步骤、工具、子代理没有任何产品可见的工作面。[ui-subagent](../代码文件/packages/client/ui-subagent/README.md)、审批、交付物各自能渲染，但各说各的词汇。

这会让 C 端用户把五类问题当作一个问题来抱怨：

- **不可见。** 对话上看不出用了记忆，也看不出助手记住了。一个正确答案和一个碰巧正确的答案长得一模一样。
- **不可控。** 对出厂 provider 而言记忆库是只读的，写入走异步批次，用户不离开对话就无法纠正、遗忘或改范围。
- **没有心智模型。** 记忆只是一张平坦的列表，没有来源、没有时间、没有与产生它的对话之间的关系，于是"记忆库"读起来像一个不透明的数据库，而不是用户自己的知识。
- **执行体不透明。** 长任务看起来就是等待。子代理、工具调用、成本没有共同的面，用户分不清"在干活"和"卡住了"。
- **失败即失真。** 降级召回、服务不可达、空账号，除非用户点开面板，否则全都显示成"这里什么都没有"。

往侧边栏加标签页解决不了其中任何一条。这些失败的共同点是：某个能力行动的那一刻，对话界面没有显示任何东西。

## Proposal

把记忆与执行体活动做成**对话原生的、可检视的、可纠正的**。每个能力都在对话中行动；每次行动都在它发生的那块界面上留下可持久、可解释的痕迹；每个持久效果都可复核、可撤销。

### 设计原则

1. **对话是主界面。** 记忆和执行体的工作在使用的现场就地展现，而不是藏在某个导航条目后面。独立的记忆页只用于浏览与管理，永远不作为记忆唯一的出现位置。
2. **来源优先于断言。** 每次召回都带范围、来源和时间。每次写入都带接收状态，未被接受的写入绝不显示为已存储。每条库内条目都能链回产生它的对话或手工写入。
3. **记忆是上下文，不是数据库。** 用户对记忆的心智模型是"助手知道我什么、知道这个项目什么"。按时间、按项目、按它所支撑的决策来组织，而不是按原始表结构。
4. **执行体展示工作，而不是等待。** 长任务渲染成步骤时间线，子代理、工具、审批、交付物在同一块面上，每一项都说清自己为什么存在。
5. **渐进披露。** 用户先看到一行摘要，再展开成步骤、召回内容或 diff。复杂度按需出现，绝不默认铺开。
6. **不可逆的操作必须确认。** 写入持久存储、删除、跨范围提升、派发后台任务，行动前先问。
7. **知识与记忆是两种不同的权威。** 召回的偏好与被引用的制度绝不渲染成同一种东西，回答要说明它依据的是哪一个。放宽对其中任何一种的访问权限，都要先问。
8. **没有记录、报告与人，就没有进化。** 执行体之所以改变，是因为它的执行记录与记忆构成了一份用户读过并批准的理由，而不是因为它自己决定了要变。

### 信息架构

| 页面 | 负责 | 用户的主要任务 |
|---|---|---|
| 首页 | 进行中的工作、运行中的执行体、待批事项、最近的交付物 | "现在在发生什么？" |
| 对话 | 消息、内联记忆、计划与步骤时间线、审批、产物侧栏 | 完成任务 |
| 记忆中心 | 集合、时间线、进化、来源、diff 审核、图谱、隐私 | "它知道什么，我同不同意？" |
| 执行体中心 | 预设、其行为契约、能力、成本、记忆策略、执行记录与进化报告 | 组合并信任一个执行体 |
| 执行体广场 | 发现、检视、安装、发布、治理执行体 | "有没有现成的执行体能干这个？" |
| 知识中心 | 个人、组织、企业集合，提升、共享与索引版本 | "什么是权威的，谁能看到？" |
| 产物与收件箱 | 交付物、定时任务、后台作业、等待用户的审批 | 收集与复核产出 |
| 工作区主页 | 项目事实、约定、决策、最近会话 | 续上一个项目 |
| 设置 | 账号级记忆策略、留存、导出与删除、模型与成本上限 | 设定默认值 |

首页取代当前"会话列表"作为落地页。会话列表保留为侧边栏里的一个分区，不再作为产品正门。

### 对话界面

对话新增四个内联元素，每个都是既有持久事件的投影，而不是新的真相来源：

- **召回条。** 首个流式 token 之前，一行紧凑文字说明召回了多少条、来自哪个范围。展开后逐条显示范围、来源、时间，并允许对某一轮临时排除某条（对应 [autosave 活动](../代码文件/packages/memory/memory-autosave/README.md) 的投影）。
- **记忆透镜。** 当前会话的常驻侧栏，列出正在生效的东西：用到的项目事实、用到的全局偏好，以及按"项目指令优先"裁决过的冲突。用户可以一键对某条记忆在本会话内静音，会话会记录这次排除。
- **写入受理。** 一轮结束后，记忆增量卡片说明执行体提交了什么，并给出明确状态：排队中、已接收、已入库、失败、未知。未知结果绝不渲染成成功；只有在结果确定安全时才提供重试。
- **记忆 diff 审核。** 对自动抽取的内容，卡片提供接受、编辑、拒绝，通过后才进入常规记忆。新用户默认开启审核，可按范围放宽为默认接受。

执行体活动在所有包里使用同一套词汇：

- **步骤时间线。** 每个模型步骤一行：意图摘要、调用的工具、耗时、token。展开可见工具参数与结果，可复制。
- **子代理树。** 被委托的工作嵌套在派生它的那一步下面，有自己的状态；失败的子代理把失败显示出来，而不是消失。
- **审批卡。** 被阻塞的操作说明会改什么、改在哪里、拒绝后会发生什么；文件写入、shell 命令、跨范围记忆操作共用同一种卡片类型。
- **产物侧栏。** 本轮产生的文件、计划、交付物收集在侧栏，重新加载会话后仍然存在。

### 记忆中心

记忆中心把"只有面板里的库"扩展为同一份数据上的四个视图：

- **集合。** 工作区与全局范围作为一等集合，显示条目数、最近活动，以及一条健康状态行，区分关闭、未配置、不可用、为空四种情况。
- **时间线。** 记忆条目按时间排序、按项目分组，每条可展开到来源（哪一轮对话或哪次手工写入）、它支撑了哪些决策、以及修改历史。纠正是新建版本，而不是静默覆盖。
- **图谱。** 仅在 provider 暴露关系时才绘制条目之间的关系；图谱是列表旁的探索工具，绝不是默认视图。
- **隐私。** 按范围的留存策略、导出、删除，并说明传播延迟。把工作区事实提升到全局记忆需要一次同时点名两个范围的显式确认。

批量操作使用两次点击或输入确认，每个破坏性操作按条目报告结果，而不是一个乐观的全局提示。

### 执行体中心

预设从"配置菜单"变成可检视的对象。每个预设页说明它适合做什么、可以用哪些工具与记忆范围、行动前会问什么、最近运行中观察到的成本与时长，以及它如何进化。用户从已有预设组合新预设；记忆策略与执行体工作流独立选择，与 [MemoryBear 方案](../.agents/notes/proposed/feature/2026-11-13-memorybear-integration-plan.md) 中的接缝一致。创建、分叉、进化都作用在 [registry](../代码文件/packages/preset/agent-preset-registry/README.md) 已按 revision 保留的声明式预设上；界面只增加审核与证据，不引入第二套组合模型。

### 执行体广场

广场是**成品执行体**的分发面——一个人设、一条工作流、一套记忆策略、以及它可用的工具——而不是包目录。[插件市场](../代码文件/docs/user/guide/plugin-market.md) 仍然是扩展运行时能力的开发者面；两者不共用页面。

**发现。** 条目按用户要办的事分组（"调研一个市场"、"维护一个代码库"、"给孩子当家教"），而不是按厂商或模型分组。排序使用真实运行的已验证证据——已完成会话数、无需人工重试即完成的任务数、三十天留存——绝不使用安装量，因为安装量奖励的是推广而不是有用程度。精选集合明确标注为编辑推荐。搜索理解任务式表述，并把三个可比的执行体并排呈现，而不是一列几乎相同的同质品。

**执行体详情。** 每个详情页在安装按钮之前说明：行为契约（做什么、拒绝什么）、它要求的**工具授权**以及其中哪些会触碰文件系统、网络或 shell、**记忆声明**（读哪些范围、写哪些范围、是否自动写入）、它无法绕过的审批策略、需要的模型能力、最近运行的成本区间、带版本间 diff 的版本历史，以及只允许来自真实会话的评价。记忆声明不完整的执行体不能发布。

**安装与启用。** 安装把一个版本钉死的预设复制进用户的预设名单，并展示能力 diff——工具、记忆范围、审批策略——要求显式确认。更新绝不静默扩大授权：增加工具或记忆范围的版本需要重新确认，移除的版本自动生效。用户可以把已安装的执行体分叉成可编辑的私有副本；广场记录分叉血脉，使归属关系不丢失。

**发布。** 发布运行作者无法豁免的闸门：提示注入与工具范围静态审查、记忆声明完整性、在类目固定对话上的一次沙箱试运行、以及一个声明的支持联系方式。发布者身份与之后每次更新都留有审计痕迹。已发布执行体的记忆策略是声明的，绝不继承自发布者自己的账号。

**信任阶梯。** 新执行体标注为*已验证*（通过闸门），只有在实测真实运行后才升为*已证实*，遇到被报告的事故则降一级。下架、撤除与举报都能从详情页一步完成；被撤除的版本不能再安装，但不会删除用户已分叉的副本。

### 基于记忆的执行体进化

执行体的成长——人设、提示、技能、工具习惯——由记忆驱动，且每一次变更都可审核、可归因、可回滚。这个环路有五个阶段，永不跳步。

1. **采集。** 信号来自记忆与会话：被接受和被拒绝的记忆 diff、反复出现的人工纠正、用户对模型输出做的编辑、有无重试的任务结果、跨会话的失败模式，以及明确指令（"以后都这样回答"）。每条信号都附着在产生它的对话与记忆条目上。
2. **提案。** 系统把信号转成**类型化的变更提案**，目标集合是固定的——人设文本、提示段落、技能模板、工具偏好、召回策略——每项都带 diff、支撑它的证据引用，以及它的影响半径。提案进入执行体中心的审核队列，绝不在生成时直接生效。
3. **影子。** 提案在触及实时回合之前，先在该执行体的历史录屏会话上评估。比较结果展示新版本会在哪些地方给出不同回答；改变行为超出其声明影响半径的提案，影子评审不通过。
4. **提升或拒绝。** 提升会写入一个新版本，附带说明、证据引用和批准人。拒绝保留记录，使同一坏提案不能悄悄复发。
5. **回滚。** 任何版本都能一步恢复。历史是版本列表而不是变更日志，所以恢复是选择一个点，而不是回退一条链。

**记忆拓扑。** 三个范围让进化不会污染用户没有选择共享的内容：

| 范围 | 是什么 | 由谁进化 | 默认 |
|---|---|---|---|
| 个人适配 | 该用户这份执行体实例：语气、习惯格式、本地偏好 | 只进化该用户自己的副本 | 开，在每个回合卡上可见 |
| 执行体记忆 | 执行体的共享行为，由所有安装者继承 | 只能经审核和新版本 | 关 |
| 工作区记忆 | 项目的事实与约定 | 绝不隐式吸收进执行体记忆 | 被授权时读取，绝不复制 |

进化在获授权时可以读取工作区记忆，但不得把它提升进执行体记忆；把工作区事实提升是用户在记忆页上的动作，不是进化的产物。

**审批级别。** 风险由变更目标决定，而不是由模型的置信度决定：

| 变更 | 级别 | 闸门 |
|---|---|---|
| 语气、详略、输出格式的个人适配 | 低 | 自动生效，在回合卡上通知，一键回滚 |
| 个人副本中的技能模板、召回策略、工具偏好 | 中 | 单次确认，带 diff 与证据 |
| 共享执行体记忆中的任何内容、任何改变授权的变更 | 高 | 禁止由进化产生；只能由人经广场审核发布新版本 |

**跨用户聚合。** 共享执行体的进化可以在共识与不含记忆内容的前提下，从跨用户的聚合信号中学习——任务成功率、纠正频率、失败类别。派生自某个用户私有记忆的行为，绝不会进入另一个用户的回合；产品必须在进化页上明示这一边界。

**可见性。** 执行体中心的进化视图列出每一项提出、生效和拒绝的变更，附带证据、产生的版本、以及逐项回滚。记忆中心的进化视图回答反向问题：我的哪些记忆塑造了这个执行体，如果我删掉它们会发生什么。

### 知识库

记忆记录发生过什么、从行为中推断；知识库存放的是一个组织认定**为真且可引用**的东西——文档、制度、合同、流程手册、产品规格——每一条都有版本、负责人和生效日期。两者不共用存储，也不共用引用样式。知识通过自己的能力接缝进入 harness，具备 Service Definition、provider 和消费者，结构与 [memory](../代码文件/packages/memory/README.md) 一致；任何消费者都不依赖某个厂商的存储模型。

#### 层级

三个层级的差别在于**谁拥有内容、谁能读、谁能改**。高层级不会自动继承低层级的内容，因为一条未被批准的个人笔记绝不能凭位置就变成组织制度。

| 层级 | 归属 | 内容 | 默认可读 | 默认可写 |
|---|---|---|---|---|
| 个人 | 单个用户 | 笔记、草稿、个人参考资料、保存的回答 | 仅本人 | 仅本人 |
| 组织 | 单一租户内的团队或部门，设有具名维护者 | 流程、决策、约定、产品与项目知识 | 团队成员 | 具名维护者，带审计痕迹 |
| 企业 | 由策略负责人治理的租户 | 制度、合同、法务与合规文本、安全规则、全组织标准 | 租户内所有人 | 仅策略负责人，生效前需审核 |

团队共享是**组织层级内部的一个共享单元**，不是第四个层级。企业内容是低层级引用的权威来源，它绝不自动吸收低层级内容。

#### 升级策略

"升级"指三种彼此独立、界面上绝不能混为一谈的操作。

**层级提升**——内容上移一个归属层级：

- 提升是一次显式提案，包含具名目的地、批准人、脱敏要求和源条目链接。原件留在原处，晋升出的副本记录来源（copy-on-promote）；源条目绝不被静默移动或删除。
- 禁止批量提升。敏感度无法分类的条目不得提升；会改变企业制度行为的提升需要策略负责人审核，而不只是层级批准人。
- 提升之后两份副本因溯源而关联，但**不同步**：之后的个人编辑不改变组织副本，组织副本的变更也不覆盖个人草稿。撤销企业副本走声明的审核路径，而不是删除条目。
- **知识绝不由执行体提升。** 进化可以提议从重复出现的模式中创建知识条目，但提案最多只能指向个人层级；每一次跨层级移动都是由对该目标层级有权限的用户执行的动作。

**索引升级**——嵌入模型、分块器或解析器变更：

- 索引并存且带版本。新索引在旧索引继续服务时构建，用固定查询集评估召回与排序回退，然后原子切换，并保留上一版本供回滚。
- 升级要说明成本、耗时，以及哪些查询的答案会变；答案会变的查询在切换前以 diff 呈现。

**权益升级**——租户升级套餐或层级，改变容量、留存或可用知识功能。它本身绝不改变内容归属或可见性；可见性是独立决策，需要独立确认。

#### 共享策略

共享由两条正交的轴决定，因为把两者混在一起正是泄露的来源：

| 轴 | 选项 | 由谁设定 |
|---|---|---|
| 访问权 | 私有、指定人员、团队、组织、企业 | 条目所有者，且不得超出层级所允许的范围 |
| 用途 | 引用（执行体可引用）、编辑（协作者可修改）、发布（可成为执行体的知识授权） | 目标层级的所有者 |

界面与后端共同执行以下规则：

- **访问权默认收窄，放宽总要询问。** 扩大某层级的可读人群、增加一个人、允许执行体引用某条目，是三次独立的确认，每次都以**人数**而不是层级名称说明结果受众。
- **撤销对新请求立即生效，对已物化的引用如实说明**：已经引用过某文档的执行体要显示哪些回合持有该引用，这些引用作为历史事实保留并附撤销提示，而不是凭空消失。
- 对外共享——租户之外的任何人——在组织与企业层级默认关闭，需要策略负责人，带有效期，并产生审计记录。被对外共享过的条目若要从外部收回或提升回来，必须先审核披露了哪些内容。
- 每个条目带敏感度分级；分级变更会重新评估既有共享，并呈现由此产生的收窄，而不是静默执行。
- 执行体的知识授权是声明式的——**哪些层级、哪些集合**——绝不是一份文档清单；因此之后加入集合的文档由集合自身的访问规则治理，而不是由执行体安装时的快照决定。

#### 对话与执行体集成

- 知识引用自有其卡片，与记忆召回条分开：显示集合、条目、版本与生效日期、以及来源层级。若被引用的文档此后发生变更，呈现为过期引用，并链接两个版本。
- 当知识与记忆冲突时，界面说明谁胜出及原因：分层权威压过召回的个人偏好，且冲突在回合卡上保持可见，而不是被隐式裁决掉。
- 执行体因获授权的知识不覆盖该问题而拒答时，要明说，并点名哪些集合可以覆盖它。**空检索绝不渲染成"不存在这样的信息"。**
- 知识中心列出各集合、其层级、维护者、共享状态，以及当前引用它们的执行体；没有维护者的集合或已到期的对外共享会在首页被标出。

### 执行体执行记录

执行体的每一次启用都写一条持久的**执行记录**：按执行体驱动的回合计一条，而不是按会话计。记录是进化的证据底座，也是其他一切事项的审计线索，因此是**只增不改**的，一旦关闭即不可变更。更正通过追加后继记录完成，绝不改写历史。

一条记录包含：

- **身份与版本。** 哪个执行体、哪个版本、生效的是哪一版个人适配——即真正运行了什么，而不只是一个名字。
- **输入类别。** 工作目录、是否由子代理或定时任务驱动、用户意图的归类，以及任何会把私有内容复制出会话的东西——后者一律不记录。
- **结果。** 完成、人工重试后完成、放弃、失败（带原因类别）或中断。只有工作达到了用户要求的状态才算"完成"，而不是最后一个模型步骤返回了就算。
- **成本与时长。** 分词阶段的 token、按工具统计的调用次数、耗时，并把审批等待时间与工作实际时间分开。
- **信号。** 用户做出的纠正、工具失败、审批被拒、记忆召回的命中与未命中、知识引用，以及被渲染出来的降级。
- **溯源。** 每个字段链接到产生它的会话事件，使进化报告里的任何主张都能解析到真实的一轮。

**记录的隐私。** 记录存的是度量而非转录：计数、类别、引用。任何会引用私有记忆或知识内容的字段，在用户打开它所指的那一轮之前都不可见。记录遵循其所在层级的留存策略，用户可以看到、导出、删除自己的记录——删除会移除度量，但保留"这次执行存在过"这一事实，以便成本与审计总数保持正确。

**访问权。** 执行体的所有者看到自己的记录。团队看到它共享的执行体的聚合记录，永远看不到个人的转录内容。企业策略可以要求企业注册执行体的记录保留一段声明期限，界面必须说明某条记录正处于这样的保留锁定之下。

### 进化报告

进化报告是用户批准的那个对象。它把执行记录与记忆信号聚合为一份"执行体该怎么改"的提案，并且刻意做成**一份带决策的文档**，而不是一次静默的后台变更。

**生成。** 报告可按需生成、按用户设定的周期生成，或在积累了达到阈值的新记录时生成——绝不在没有可见待办项的情况下持续在后台进行。生成时说明它读取了哪个记录窗口、哪个记忆范围、哪个版本。证据不足的报告要明确说证据不够，并且不提出任何提案。

**内容。** 每份报告都包含：

- **记录说明了什么。** 窗口内的成功、重试、放弃与失败率，与上一窗口的对比趋势，以及执行体表现不佳的类别。
- **记忆解释了什 么。** 哪些被召回的记忆支撑了成功的运行、哪些纠正反复出现；**重复出现的纠正模式是报告能携带的最强证据**。
- **提案。** 每项都是带目标、diff、证据引用、预期效果、影响半径与置信度的类型化变更。没有引用的提案不会出现。
- **它不会改什么。** 授权、记忆范围与知识访问在每份报告上都声明为不在范围内，因此批准绝不能被理解为一次权限变更。
- **风险与回滚。** 每项提案携带的风险级别，以及各自可以回退到哪个版本。

**审核与批准。** 报告按"已生成 → 审核中 → 已批准/已拒绝 → 已生效"流转。审核人可以整份接受、逐项接受、编辑某项提案的文字，或附理由拒绝，理由会保留在记录中。被拒绝的报告保留其证据，使同一结论不能悄悄复发。**批准由用户做出，执行体永远不会批准自己。** 若报告的提交者就是会被它改变的那个执行体，必须明确标注，并且审批控件要直白说明这个决定属于谁。

**生效。** 批准会写入一个新的执行体版本，以报告作为其依据，在任何实时回合使用它之前执行影子评估，然后才启用。影子评估失败的报告退回审核，而不是部分生效。已生效版本中的每项提案都能链回报告与产生它的记录。

**事后评估。** 每个已生效版本会与被它替换的版本进行一段对照窗口的观察，进化视图展示报告的预期效果是否真的发生。未能改进——甚至回退——的版本会带实测对比被标记为待回滚，而这个结果本身也会作为下份报告的证据被记录。

### 状态模型

记忆、执行体、服务状态在所有界面上共用一套词汇：

| 状态 | 含义 | 用户看到 |
|---|---|---|
| 关闭 | 用户对某个范围或某一轮关掉了该能力 | 一行安静的提示，附一键开启 |
| 未配置 | 没有绑定 provider | 安装引导，并说明配置之后会发生什么 |
| 降级 | 召回失败或超时，本轮继续 | 失败原因类别，而不是空结果，并提供重试 |
| 不可用 | 服务不可达 | 受影响范围上的服务健康横幅 |
| 结果未知 | 写入已提交、结果未确认 | 明确的未知状态，不作成功声明 |

服务降级时开关仍显示"开"，在上述任何一个状态模型里都是缺陷。

### 后端前提

界面只表达 provider 能证明的事。内联召回条、写入受理、时间线视图读取会话日志与现有活动端点。删除、图谱、遗忘需要出厂 MemoryBear API key 未暴露的 provider 端点；在 provider 声明该能力之前，这些页面保持隐藏，与 [ui-memory](../代码文件/packages/client/ui-memory/README.md) 中既有的 `canForget` 行为一致。

### 交付顺序

1. **信任：** 内联召回条、写入受理卡、统一状态词汇、对话内的服务健康。不需要新的后端能力。
2. **控制：** 记忆透镜、diff 审核、带来源的时间线、按范围的留存与导出。
3. **能力：** 删除、图谱、遗忘、跨范围提升，以及在首页上呈现主动记忆提案。
4. **分发：** 执行体广场的浏览与详情页、带能力 diff 与授权重确认的安装、分叉血脉。
5. **进化：** 信号采集、类型化提案、影子评审、版本提升与回滚、个人与共享范围及其审批级别。低风险的个人适配先上线；共享执行体进化跟随广场的发布闸门。
6. **治理：** 发布审核、信任阶梯、举报与下架、聚合信号共识控制。
7. **知识：** 带层级与版本的引用卡片、具备独立检索接缝的个人集合、作为受审提案的层级提升。
8. **共享知识：** 组织与企业层级、访问权与用途两条轴、带有效期与审计的对外共享控制、可回滚的索引版本升级。
9. **记录与报告：** 带结果、成本、信号与溯源的执行记录；带证据引用与逐项批准的进化报告；生效后的对照窗口及其回滚标记。

## Alternatives considered

独立的记忆应用被否决，因为它把记忆与赋予其意义的对话割裂开来。纯聊天加隐形执行体被否决，因为它既无法建立也无法修复信任。把控制项藏进设置被否决（可发现性），只做设置侧策略也被否决，因为策略是在上下文里选择的。图谱优先的记忆页被否决，因为浏览图谱不是用户的任务。完全自主的"写了就忘"被否决，因为它无法被解释、纠正或回滚。

保持记忆能力独立于执行体工作流，保持界面是持久事件的投影而不是第二个存储。保留面板用于深入检视，但取消它作为唯一界面的地位。保持广场与插件市场分离，因为一个捆绑了运行时包的插件和一个声明了授权的成品执行体是不同的对象，审查方式也不同。否决共享执行体的自主自我修改：进化只提案，由人提升，回滚路径是一条版本列表。把知识做在记忆旁边的独立能力接缝上、而不是做成记忆的一个范围，因为被引用的制度与被推断的偏好需要不同的权威、留存和共享控制。否决"高层级自动继承低层级内容"的层级模型：那正是一条未批准的笔记变成制度的路径。否决就地提升，以及晋升副本与源之间的自动双向同步，因为两者都让披露与撤销变得不可追溯。否决一切形式的持续后台自我进化与自我批准：报告才是审核对象，由人批准，而一个会被它自己改变的执行体永远不是批准人。

## Acceptance criteria

- 首次使用的用户无需打开文档就能找到记忆开关，并能解释某条记忆为什么被召回。
- 每一次模型可见的记忆读写都有对应的内联界面状态，包括降级、不可用和结果未知；没有证据时任何界面都不声称成功。
- 用户仅凭对话就能遗忘一条记忆、纠正一条记忆、对某一轮静音记忆。
- 工作区范围在界面上保持隔离：provider 没有返回给某个范围的条目，绝不会出现在该范围里。
- 每条库内条目都能解析到来源，每次纠正都保留上一版本。
- 一次长任务把步骤、子代理、审批、产物渲染在同一块面上，失败的子代理显示为失败。
- 五种状态值在每个界面上渲染出可区分的表现，文案由 locale 字典拥有。
- 执行体详情页在安装前说明每一项工具授权与记忆范围；增加其中任何一项的更新必须重新确认，移除任何一项的更新无需确认即生效。
- 记忆声明不完整的广场条目不能发布，被撤除的版本不再可安装。
- 每一项进化变更都能解析到其证据、目标、审批级别和版本；高级别变更在不经人发布版本的情况下无法生效。
- 影子评审失败会阻止提升；回滚任何执行体版本都能一步恢复此前行为。
- 删除一条曾塑造执行体的记忆，会显示哪些提案随之失去证据；不存在保留着已被用户删除的证据的提案。
- 依赖某条知识的回答会渲染带集合、层级、版本与生效日期的引用卡片；文档变更后的引用渲染为过期引用，并链接两个版本。
- 个人条目未经对目标层级有权限的人审核提升，无法进入组织或企业集合；提升后源条目留在原处且未被修改。
- 放宽共享两条轴中的任意一条——可读人群或引用用途——都要先询问，以人数说明结果受众，并产生审计记录；对外共享必须带有效期。
- 撤销访问权对新请求立即生效，并把既有引用标记为已撤销而非删除；执行体的授权跟随其集合，而不是安装时的快照。
- 每一次由执行体驱动的回合都追加且仅追加一条不可变的执行记录，携带身份、版本、结果、成本、信号与溯源；更正一条记录是追加后继记录，而不是编辑它。
- 没有用户批准过的进化报告，就不存在任何新版本的创建、启用或授权扩大；报告中的每项提案都能解析到至少一条被引用的记录；影子评估失败的报告不能生效。
- 每个已生效版本都有一段与被替换版本的对照窗口，发生回退的版本带实测对比被标记为待回滚，而不是悄悄保留。
- 执行体不能撰写并批准会改变自己的那份报告；审批控件要点名这个决定属于谁。
- 索引升级在旧索引继续服务时进行，报告答案会变的查询，原子切换，并可回滚到保留的版本。
- 空的知识检索渲染为"授予的集合未覆盖此问题"，并点名可以覆盖的集合，绝不用"不存在这样的信息"表达。
- GUI 变更满足仓库的真实服务器验证与录屏规定，两种布局在手机宽度下都可用。

## Open questions

自动写入默认走 diff 审核还是默认接受，仍是产品决策。首页是否成为新安装的默认落地页影响引导流程，需要留存数据的支撑。删除与遗忘页面取决于 MemoryBear 集成方案中记录的 provider 能力决策。每轮成本展示需要先定一次 token 记账接缝，才能在对话界面上承诺。

广场方面待定：排序是暴露原始证据还是只显示信任等级、发布者如何证明支持联系方式、分叉出的执行体能否在保留归属的前提下再发布。进化方面待定：影子评审只跑用户自己的会话还是加上类目固定集、低风险适配在生效前需要积累多久的证据、用户能否在导出已进化执行体的同时把自己的个人记忆留在原处。知识方面待定：敏感度分类法以及它是由分类器驱动还是声明式、提升能否允许单向同步、团队改名或解散时谁算维护者、企业法务文本在提升前如何脱敏、企业层级在冲突时是否有权压过组织集合。记录与报告方面待定：一个窗口需要多少条记录才允许提出提案、对照窗口按回合还是按周衡量、用户能否在零风险提示下不阅读就批准一份报告、记录的留存与企业保留锁定如何交互。这些都不阻塞信任阶段与分发阶段。

## Risks

"已接收未入库"的状态报告可能暴露产品无法控制的后端延迟；界面必须如实显示未知，而不是把它抹平成成功。对出厂 provider 而言，图谱与遗忘页面会一直为空或隐藏，直到端点存在。过密的步骤时间线会压垮非技术用户；渐进披露是前提要求，不是打磨步骤。界面文案在共享屏幕上有泄露个人记忆内容的风险，敏感条目需要默认打码。自动记忆需要容易关闭，而模糊的自主边界比缺少功能更快地侵蚀信任。

广场风险：一个满是同质品的市场，会奖励发布得最多的那方；安装量极易被刷；列出的工具授权可能在受审版本与最终安装的版本之间漂移；评价可以被制造。下架无法收回已被分叉的副本，所以纪律必须建立在"安装时授予最小权限、扩大时重新确认"上，而不是对列表本身的信任。

进化风险：适配会形成信息茧房——执行体针对用户过去优化，却不再呈现用户下一步需要的东西；附着在已删除记忆上的证据可能被误读为仍然有效；影子评审只衡量已记录的行为，所以提案可以"通过"却没有改进的证据；个性化会悄无声息地累积成一个用户从未选择过行为的执行体。因此每个提案都需要一行反事实结论，以及一个可见的"没有你的适配时，这个执行体会怎么做"对比；并且适配永远不得改变授权。

知识风险：层级提升是本文档中风险最高的操作，因为它把私人文本变成别人家执行体会引用的权威；一次范围配错就是任何逐条界面都撤回不了的披露，而一个过宽的敏感度分级会让人绕开功能直到它不可用。过期引用比缺失引用更危险，因为建立在被取代制度上的自信回答，看起来和正确回答一模一样；生效日期与过期标记是强制项，不是装饰。索引升级悄悄改变答案质量、解散的团队留下仍可读的孤儿集合、执行体的授权活得比它获批时的受众更久，这些都是需要常驻监控而不是一次性审核的失效模式。

记录与报告风险：如果"步骤返回了"就被计为成功，每个执行体都会显得在进步；而不读就批准报告的用户，等于给了自我修改一枚橡皮图章。在很少的回合上做对照窗口，会把噪声显示成改进或回退；界面必须拒绝断言它无法测量的趋势。记录还会累积成第二份更安静的行为数据副本，所以留存与删除必须是真实且可测的，而不是政策文案。最后，一个学会了"生成用户愿意批准的报告"而不是"做出有用的改变"的执行体，是在优化审批而不是优化工作，只有生效后的对照才能发现它。
