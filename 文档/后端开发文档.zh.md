# 后端开发文档：记忆、执行体、广场、进化、知识库

[English](后端开发文档.md) | 中文

## 范围

本指南把[产品设计](2026-11-18-consumer-memory-agent-product-design.md)落成可以在真实 `dsh` 架构上施工的 Host 工作。它说明哪些包拥有哪些行为、客户端调用哪些 Remote 命名空间、记录哪些持久事实，以及生产部署需要哪些防护。

Host 同样是一棵 Cordis 插件树。新能力就是一个贡献服务、事件与注册副作用的包；客户端通过由 `@deepseek-ai/dsh-api-gateway` 依据 `@Remote` 描述符生成的 Remote 命名空间访问它。这里不引入第二套组合模型。

## 架构落点

| 层 | 包 | 角色 |
|---|---|---|
| 能力接缝 | `packages/memory/memory`（现有） | 长期记忆的 Service Definition |
| 知识接缝 | `packages/knowledge/knowledge`（新增） | 可引用知识的 Service Definition，位于记忆旁边而非其内部 |
| Provider | `memory/memory-bear`（现有）、`knowledge/knowledge-<vendor>`（新增） | 厂商存储与检索 |
| 消费者 | `memory/memory-autosave`、`memory/tool-memory`、`memory/memory-agent` | 回合内召回与写入、模型工具、执行体创建 |
| Remote 控制器 | `packages/api/memory-controller`（现有），新增 `knowledge-controller`、`agent-center-controller`、`plaza-controller`、`evolution-controller` | 以收窄的 Remote 命名空间暴露给客户端的 Host 服务 |
| Remote 组装 | `packages/api/remotes` | 必须选中每个新命名空间与转发事件 |
| 传输 | `packages/api/gateway` | 类型化一元调用、多路复用流、事件转发；不拥有领域逻辑 |
| 预设 | `packages/preset/agent-preset-registry` | 声明式执行体定义与 revision 保留；进化结果落在这里 |
| 持久化 | `packages/session/*`、`packages/storage/*` | 持久事件日志与非会话存储 |

每个新包遵循仓库规则：服务包默认导出服务类；函数插件具名导出 `name`、`inject`、`Config`、`apply`；注册经由 `ctx.effect` / `ctx.on`；可选服务用 `ctx.get(name)` 读取。

## 能力接缝

### 记忆

接缝保持原形：一个 Service Definition、一个 provider、若干消费者。两处新增：

- **回合级排除。** 召回返回条目标识；loop 的提示组装在该回合丢弃被排除的标识，并把这次排除记录为持久事件，使回放能复现同一份提示。
- **纠正即版本。** `correct` 追加一个带来源的新条目版本。记忆库读取解析最新版本；时间线展示全部版本。

### 知识

新增接缝，同样是三种角色。Service Definition 拥有：集合成员关系、带生效日期的条目版本、引用解析、提升提案、访问/用途授权模型，以及索引版本。Provider 拥有存储、分块、嵌入与检索。消费者包括：提示组装（引用注入）、`knowledge` 模型工具、知识中心 Remote，以及执行体授权解析器。

Definition 强制以下规则，因为界面做不到：

- 提升是一个带批准人与目的地的提案对象；没有任何 API 路径可以就地移动条目。
- 授权写的是集合与层级，绝不是条目清单。
- 索引版本并存；每个集合同一时刻只有一个活动版本回答查询，切换是原子的。
- 引用解析返回被引用的那个版本，而不是当前版本；过期引用是一等值。

### 执行记录

在 `packages/memory` 与 `packages/core/agent-loop` 边界上的消费者：loop 为每个执行体驱动的回合发出一条记录，但不拥有记录的存储。记录存储位于 `packages/storage`，由新包 `packages/agent-center/records` 提供仓储。

记录字段在写入时固定：执行体 id、版本 id、适配 revision、工作目录类别、触发类别、带原因类别的结果、token 与时长度量、按工具统计的调用数、审批等待时间、信号列表，以及事件溯源引用。不存储转录内容；任何会承载私有文本的字段只存引用。

记录只增不改；更正会追加一条带 `supersedes` 引用的后继记录。

### 进化报告

生成器是新包 `packages/agent-center/evolution` 中的服务。它读取一个记录窗口与一个记忆范围，计算指标与趋势、提取重复出现的纠正模式，并让模型在固定的目标集合上提出类型化变更。模型绝不接收原始转录，只接收聚合指标与被引用的信号。每项提案必须至少带一条引用，否则在报告入库前被丢弃。

审批是一步 Host 操作：校验报告处于审核中、记录审批人 principal、针对已录制会话运行影子评估，成功后通过 `agent-preset-registry` 写入新的预设 revision、启用它，并把该版本链接到报告。

## 持久事实与持久化

新增的会话事件，全部包含模型可见事实：

| 事件 | 载荷用途 |
|---|---|
| `memory/exclusion` | 某回合从召回中排除了哪些条目标识 |
| `memory/acceptance` | 提交 id、状态、原因类别 |
| `knowledge/citation` | 集合、条目、版本、生效日期、层级 |
| `agent/execution-record` | 记录 id 及其关闭时的度量快照 |
| `evolution/report-state` | 报告 id、状态迁移、审批人、版本 id |

每一项都是 `SessionEventMap` 成员，需带 `@mode` 与 `@param` 的 JSDoc；按 `model-visible ⟺ logged` 规则，新增模型可见输入必须配事件。仅当既有判别符无法阻止不安全的解释时才提升 `SESSION_FORMAT_VERSION`；否则读取方必须容忍更新的未知事件。

记录还需要非会话存储：记录库、报告库与广场目录都是 `storage` 消费者，拥有独立于 `SESSION_FORMAT_VERSION` 的 schema 版本。删除用户记录会移除度量并保留一个匿名的存在标记，以维持成本与审计总数。

## 权限、租户与治理

- 每个 Remote 端点声明它触碰的资源；知识命名空间通过 `typert.resources` 解析 `collection` 与 `tier` 资源种类，使非 owner 的 Peer 读不到策略不允许的内容。
- 对外共享要求策略负责人 principal，产生审计记录，并在读取时强制执行有效期。
- 企业保留锁定把记录标记为声明期限内不可删除；客户端以字段形式收到锁定状态，绝不自行推断。
- 广场版本下架会阻止新的安装，但保留已分叉副本；目录行不可变，下架会追加一条状态事件。

## Provider 接入（MemoryBear 及后续）

出厂 MemoryBear provider 形状不变。按集成方案，在产品界面正式上线前必须先回答两个能力问题：

- 独立的 end-user 绑定能否隔离工作区范围（覆盖写入、召回、列表与画像），还是后端需要显式的范围字段。
- 管理 API 背后是否存在删除与图谱端点，这决定删除、图谱与遗忘视图能否展示。

两者未定之前，控制器返回带原因类别的 `degraded`，界面停留在设计所定义的状态模型内。

## 可观测性

每回合的结构化遥测：召回延迟与命中数、排除数、知识引用数、记录写入失败、报告生成耗时、审批延迟、影子评估失败率、安装确认率，以及对外共享创建数。每个失败都携带封闭联合中的原因类别，让看板能区分 provider 不可达、降级与被拒绝。

上线第一天就值得建立的告警：索引切换后答案变化率上升、记录超过对照窗口仍无报告、未知写入状态超过阈值，以及任何点名受众大于该集合层级所允许范围的授权放宽。

## 测试

- 能力接缝测试：记忆与知识各有一份用假 provider 的 Definition 测试；消费者测试断言提示组装、引用渲染与排除回放。
- Remote 测试：描述符生成、通过执行器（而非靠 schema 省略）验证访问拒绝，以及未知结果行为。
- 持久化测试：新事件往返、回放复现提示，迁移读取路径返回 `migration-required` 而不是猜测。
- 报告流水线测试：必须带引用、影子失败阻止提升、回滚恢复上一 revision。
- 当 loop、session 或事件形状变化时，两个 SDK 的期望输出需在同一变更中更新。

## 交付顺序

1. 记忆控制器扩展（范围、游标、排除、纠正、时间线）与受理事件。
2. 执行记录发射与记录库。
3. 进化报告生成、影子评估，以及写入预设 revision 的审批。
4. 知识接缝 Definition、首个 provider 与知识控制器。
5. 广场目录存储、安装 diff、发布闸门。
6. 治理：保留锁定、对外共享审计、下架状态。

## 风险与缓解

| 风险 | 缓解 |
|---|---|
| 记录体量无上界增长 | 按层级留存、入库前聚合，以及每执行体硬上限 |
| 报告生成器为审批而非结果优化 | 影子评估加生效后的对照窗口；回退的版本自动标记待回滚 |
| 提升把私人文本泄露进组织权威 | 带具名批准人与脱敏字段的提案对象，且不存在就地移动路径 |
| 索引切换悄悄降低答案质量 | 固定评估查询集、并行索引版本、原子切换、保留回滚 |
| 过期引用被当作当前引用 | 引用携带被引用版本与生效日期，解析绝不重写 |
