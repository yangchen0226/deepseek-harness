# Front-end development guide: memory, agents, plaza, evolution, knowledge

English | [中文](前端开发文档.zh.md)

## Scope

This guide turns [the product design](2026-11-18-consumer-memory-agent-product-design.md) into buildable Web client work on the real `dsh` client stack. It names packages, slots, stores, tokens, routes, and the interaction specifications a designer and an engineer can both hold each other to.

The client is a browser plugin tree: the shell renders `'root'`, and every surface below is a plugin registering into a slot its parent declared. No page here is a new application; each is a package under `packages/client/` (in the code tree, `代码文件/packages/client/`).

## Architecture placement

| Concern | Where it lives |
|---|---|
| Page composition | `@deepseek-ai/dsh-client-ui-layout` regions plus `ui-sidebar` / `ui-sidebar-right` for the two rails |
| Conversation surface | `@deepseek-ai/dsh-client-ui-conversation` slots; new inline elements register as children of the message list or composer |
| Right rail tabs | `ctx.sidebarRightTabs.register` with a tab `kind`, body in `sidebar.right.pane.tab` |
| Remote calls | `ctx.remote.<namespace>` from `@deepseek-ai/dsh-api-remotes`, generated from Host `@Remote` descriptors |
| Shared state | `ctx.store` factories declared at registration (`store: defineStore(...)`), read with `props.useStore`, written through `props.actions.*` |
| Copy | `@deepseek-ai/dsh-client-locale` dictionaries; every visible string goes through `t` |
| Visual language | `--dsw-*` tokens from `@deepseek-ai/dsh-client-ui-theme`, controls from `ui-primitives` |
| Icons and artwork | `ui-primitives` icon set; official plugin glyphs follow the artwork skill |

Every new surface is a package, and its `/client` entry exports only `apply`, `inject`, optional `Config`, and store factory types. Feature plugins never runtime-import one another; behavior crosses through services, UI through slots.

The sidebar keeps Workspace and Session navigation and gains one entry per center. The conversation remains the default landing route until Home's abandonment metric is measured; the route is `#/home`.

### Navigation rules

- Route changes never unmount a live conversation; the conversation pane keeps its Session subscription and only its visibility changes.
- A center opened from a conversation carries the Session context in the URL (`?session=<id>`), so deep links restore the scope filter.
- The right rail is per-Session and keeps its open tab when the user switches centers.

## Conversation surface

Three inline elements and one rail, each a projection of durable events.

### Recall chip

Registers into the message list's pre-assistant slot. It reads the Session's `memoryAutosave` projection, not a new fetch.

| State | Rendering | Interaction |
|---|---|---|
| Recalled, 1–3 items | One line: "3 memories from this workspace" | Click expands item list |
| Recalled, more than 3 | "12 memories · 3 shared with you" | Expands into a paginated list |
| Degraded | Amber inline notice with cause class | Retry recalls once |
| Off | Quiet line with a one-action turn-on | Turn-on applies to this turn |
| Unconfigured | Setup link | Opens Settings memory section |

Expanded items show scope, source, time, and a "mute for this turn" control. Muting records a turn-scoped exclusion and updates the chip immediately; it never deletes the memory.

### Memory lens

A right-rail tab (`kind: 'memoryLens'`) listing the memories in play for the Session: workspace facts, global preferences, and resolved conflicts. Each row has a mute control; conflicts show which instruction won and why. Empty state states that memory is on and nothing was recalled, rather than showing an empty panel.

### Write acceptance card

Rendered after the turn's last assistant message. Reads the write events from the Session log and renders exactly one state per submitted batch:

| State | Copy intent | Action |
|---|---|---|
| Queued | Accepted, extraction pending | None; refresh |
| Accepted | Accepted by the service | None |
| Indexed | Confirmed in the library | Link to the entry |
| Failed | Rejected, reason class | Retry when the failure is retryable |
| Unknown | Outcome unknown, do not resubmit | Link to the library to verify |

Unknown never renders green and never offers blind retry.

### Memory diff review

When the provider supports reviewed extraction, the card offers accept, edit, and reject per item, with an edit that keeps the original text visible. Review is on by default for new accounts and is a per-scope setting.

### Step timeline

Extends the existing tool-call rendering into one timeline: each model step is a row with intent summary, tool chips, duration, and token count. Expansion shows tool arguments and results with copy affordances. The timeline is collapsed to one line after the turn completes, with the last failing step kept expanded.

### Subagent tree

Children nest under the spawning step, each with its own status. A failed child renders its failure and its partial output; it never disappears. The tree is capped at one level of visible nesting with an expand control at each level.

### Approval card

One component type serves file writes, shell commands, and cross-scope memory operations. It states the change, the target, the scope, and the effect of rejection. It renders blocking for destructive operations and non-blocking for reversible ones, and it always shows who is being asked.

### Artifacts rail

Files, plans, and deliverables produced during the turn collect on the rail and survive a reload. A new artifact triggers a non-modal toast with an open action.

## Memory center

Four views over one data source, sharing a scope switcher (workspace, global) and a time filter.

- **Collections.** Cards per collection with counts, last activity, and a health line distinguishing off, unconfigured, unavailable, and empty. The card's primary action changes with state: set up, retry, or browse.
- **Timeline.** Entries ordered by time and grouped by project. Each expands to provenance (the turn or the manual write), the decisions it informed, and its correction history. Correction opens an editor and appends a version.
- **Graph.** A force-directed relation view rendered only when the provider returns relations. It is a secondary tab, never the landing view, and it degrades to a plain list with a notice.
- **Evolution.** Which memories shaped which agent, and which proposals would lose their evidence if an entry were deleted. Deletion from here runs the standard two-step confirmation and shows the affected proposals.

## Agent center

One page per agent with five sections: behavior contract, capability table (tools, memory scopes, knowledge grants, approval policy), execution records, evolution reports, and versions.

- **Execution records** render as a filterable table (outcome, window, trigger) with a detail drawer that resolves each field to its session turn.
- **Evolution reports** render as a document: summary metrics, evidence citations, per-proposal cards with diff, expected effect, blast radius, and confidence. The footer carries the approval control, the approver's name, and a plain statement that the decision belongs to the user.
- **Versions** render as a list, each row offering activate and roll back, and each applied version showing its comparison window result.

Report states map to visual states: `generated` (neutral), `in review` (accent), `approved` (success), `rejected` (muted with reason), `applied` (success with version link), `shadow failed` (warning, returns to review).

## Agent plaza

Discover, detail, install, publish, governance.

- **Discover** groups by job, not vendor. Cards show the agent name, the job phrase, the trust level, a one-line capability summary, and the memory declaration summary. Ranking shows what it is ranked by; install counts never appear.
- **Detail** leads with the behavior contract, then a grant table (tool, why it is needed, what it can touch), the memory declaration, the approval policy, the model requirement, cost range, version history with diffs, and reviews that only a real session can post.
- **Install** shows a capability diff against the user's current roster and requires explicit confirmation when a version adds a tool or a memory scope. Removal applies without confirmation.
- **Publish** is a guided flow: metadata, behavior contract, grants, memory declaration, sandbox trial result, support contact, then review status.
- **Governance** surfaces reports, takedowns, and deprecations as a first-class tab, with a report action on every detail page.

## Knowledge center

Tier switcher (personal, organization, enterprise), then collections. Each collection page shows tier, maintainers, sharing state, citing agents, and version status.

- **Promotion** is a reviewed proposal flow: pick destination, state redaction, name an approver, submit. The UI shows the source item remains in place.
- **Sharing** uses two independent controls — access population and purpose — and each widening confirmation names the resulting audience in people.
- **Index upgrade** renders as a maintenance job with cost, duration, affected queries, and a rollback button while the previous index is retained.
- **Citations** in the conversation render as their own chip with collection, tier, version, effective date, and a stale marker linking both versions.

## Visual design

### Tokens

All color, spacing, radius, and type comes from `--dsw-*` tokens; components define no literal colors. Semantic mapping the screens depend on:

| Meaning | Token role |
|---|---|
| Success (indexed, applied) | positive surface + positive text |
| Warning (degraded, unknown) | warning surface + warning text |
| Danger (failed, destructive) | danger surface + danger text |
| Muted (off, rejected, stale) | muted text on elevated surface |
| Accent (in review, primary) | brand accent |

### Layout and density

- Left rail 264px, right rail 360px default and 480px expanded; the conversation column is fluid.
- Content width for reports and detail pages caps at 880px with 24px gutters, so a diff remains readable.
- Density is one setting with two values; compact mode reduces row height to 32px and hides secondary metadata behind hover.
- Below 768px the right rail becomes fullscreen, the left rail becomes a drawer, and the step timeline collapses to summaries only. Table-driven pages become card lists.

### Interaction specifications

| Interaction | Specification |
|---|---|
| Toggle a capability | Immediate optimistic state, then authoritative state from the server; a mismatch reverts with an inline explanation |
| Destructive action | Two-step, second step labels the exact object; the confirm button is never the default focus |
| Long-running job | Progress card with elapsed time, a cancel action when cancellable, and the result link on completion |
| Loading | Skeletons for card layouts, an indeterminate line for inline chips; no full-page spinner |
| Empty | State-specific copy naming the cause and one primary action |
| Error | Inline, with a retry for retryable classes and a copyable diagnostic id otherwise |
| Keyboard | `g h` Home, `g m` Memory, `g a` Agent center, `g p` Plaza, `g k` Knowledge; `?` opens shortcuts via `ui-shortcuts` |

### Accessibility and motion

Focus is visible on every control; state is never conveyed by color alone (each state carries an icon and text). Motion respects `prefers-reduced-motion`; the step timeline and the plaza cards have reduced-motion variants without transitions.

## State ownership

| Data | Channel |
|---|---|
| Session-derived (recall, writes, steps, approvals) | framework hooks over Session projections |
| Cross-pane UI state (selected scope, filters, open tab) | a declared store per page, created in `apply` |
| Server reads not tied to a Session (library, timeline, reports) | `useResource` over the Remote namespace with page-scoped caching |
| Transient local (draft, expansion) | component state |

No component subscribes manually; no module-level handle; no mirroring server data into local state. Editing flows keep drafts in component state and submit through injected callbacks.

## Copy and localization

All strings live in `packages/client/<pkg>/src/client/locales.ts` with the Chinese dictionary as the key-set source of truth and English as the second dictionary. Copy rules the design enforces:

- State copy names the consequence, not the mechanism: "Not saved yet — the service has not confirmed" beats "status: pending".
- Unknown outcomes never use success vocabulary.
- The approval control names the person: "Approve as <user>" rather than "Approve".
- English copy uses sentence case throughout.

## Performance budgets

| Surface | Budget |
|---|---|
| Center page first paint | under 400ms on the reference profile |
| Step timeline row streaming | under 16ms per update batch |
| Library paging | under 150ms per page from cache |
| Report page (500 records) | under 800ms, virtualized |
| Plaza cards | images lazy, under 120KB each |

Long lists virtualize; diff rendering truncates beyond 200 lines with an expand control; every Remote read used above the fold is prefetched on route intent.

## Testing

- Unit behavior tests per package for state mapping and copy selection.
- Slot composition tests: dispose the fiber and assert the contribution disappears (the repository's HMR-safety rule).
- Accessibility checks for focus order, contrast tokens, and reduced motion.
- Recording requirement: every GUI change in this plan ships with a real-server recording; the product design's acceptance criteria apply unchanged.
