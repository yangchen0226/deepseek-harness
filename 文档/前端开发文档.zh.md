# 前端开发文档：记忆、执行体、广场、进化、知识库

[English](前端开发文档.md) | 中文

## 范围

本指南把[产品设计](2026-11-18-consumer-memory-agent-product-design.md)落成可以在真实 `dsh` 客户端栈上施工的 Web 端工作。它点名包、插槽（slot）、store、设计令牌、路由，以及设计师和工程师可以互相校验的交互规格。

客户端是一棵浏览器插件树：外壳渲染 `'root'`，下面每一个界面都是插件，注册进父级声明过的插槽。这里的页面都不是新应用，每一个都是 `packages/client/` 下的包（在代码树中即 `代码文件/packages/client/`）。

## 架构落点

| 关注点 | 所在位置 |
|---|---|
| 页面组装 | `@deepseek-ai/dsh-client-ui-layout` 的区域，加上 `ui-sidebar` / `ui-sidebar-right` 两条侧栏 |
| 对话界面 | `@deepseek-ai/dsh-client-ui-conversation` 的插槽；新的内联元素作为消息列表或输入区的子插槽注册 |
| 右侧栏标签页 | `ctx.sidebarRightTabs.register` 声明 tab `kind`，主体注册到 `sidebar.right.pane.tab` |
| Remote 调用 | `@deepseek-ai/dsh-api-remotes` 提供的 `ctx.remote.<namespace>`，由 Host 的 `@Remote` 描述符生成 |
| 共享状态 | 注册时声明的 `ctx.store` 工厂（`store: defineStore(...)`），通过 `props.useStore` 读、`props.actions.*` 写 |
| 文案 | `@deepseek-ai/dsh-client-locale` 字典；每一个可见字符串都经由 `t` |
| 视觉语言 | `@deepseek-ai/dsh-client-ui-theme` 的 `--dsw-*` 令牌，控件来自 `ui-primitives` |
| 图标与美术 | `ui-primitives` 图标集；官方插件图形遵循美术规范 |

每个新界面都是一个包，其 `/client` 入口只导出 `apply`、`inject`、可选的 `Config`，以及供组件以类型方式使用的 store 工厂类型。特性插件之间绝不互相运行时导入；行为通过服务跨越，界面通过插槽跨越。

## 页面清单与路由

| 页面 | 新增包 | 挂载到 | 主要数据 |
|---|---|---|---|
| 首页 | `ui-home` | `main` | `home/summary` |
| 对话 | 现有 `ui-conversation` 加三个新子包 | 对话插槽 | `session/*` 流、`memory/*`、`agent/*` |
| 记忆中心 | `ui-memory-center` | `main` | `memory/library`、`memory/timeline`、`memory/evolution` |
| 执行体中心 | `ui-agent-center` | `main` | `agent/list`、`agent/reports` |
| 执行体广场 | `ui-agent-plaza` | `main` | `plaza/*` |
| 知识中心 | `ui-knowledge-center` | `main` | `knowledge/*` |
| 产物与收件箱 | 扩展 `ui-deliverables`、`ui-jobs`、`ui-schedule` | `main` | `deliverable/*`、`job/*` |
| 设置 | 扩展 `ui-settings-*` 各包 | `main` | `settings/*` |

侧边栏保留工作区与会话导航，并为每个中心增加一个入口。在首页的放弃率指标测出来之前，对话仍是默认落地路由；首页路由为 `#/home`。

### 导航规则

- 路由切换绝不卸载正在进行的对话；对话面板保持其 Session 订阅，只有可见性变化。
- 从对话打开的中心在 URL 中携带会话上下文（`?session=<id>`），使深链接能恢复范围筛选。
- 右侧栏按会话存在，用户切换中心时其已打开的标签页保持不变。

## 对话界面

三个内联元素加一条侧栏，每一个都是持久事件的投影。

### 召回条

注册进消息列表的 assistant 前置插槽。它读取会话的 `memoryAutosave` 投影，而不是发起新的请求。

| 状态 | 渲染 | 交互 |
|---|---|---|
| 已召回 1–3 条 | 一行：本工作区召回 3 条记忆 | 点击展开条目列表 |
| 已召回超过 3 条 | 12 条记忆 · 其中 3 条为共享 | 展开为分页列表 |
| 降级 | 琥珀色内联提示，附原因类别 | 重试一次召回 |
| 关闭 | 一行安静提示，附一键开启 | 开启仅作用于本轮 |
| 未配置 | 安装链接 | 打开设置的记忆分区 |

展开后的条目显示范围、来源、时间，以及“本轮静音”控件。静音会记录一次回合级排除并立刻更新召回条，绝不删除记忆。

### 记忆透镜

右侧栏标签页（`kind: 'memoryLens'`），列出本轮生效的记忆：工作区事实、全局偏好，以及被裁决的冲突。每行都有静音控件；冲突显示哪条指令胜出以及原因。空态要说明记忆已开启但本轮没有召回，而不是显示一个空面板。

### 写入受理卡

在该回合最后一条 assistant 消息之后渲染。读取会话日志中的写入事件，每个提交批次只渲染一个状态：

| 状态 | 文案意图 | 动作 |
|---|---|---|
| 排队中 | 已接收，提取待完成 | 无；可刷新 |
| 已接收 | 服务已接收 | 无 |
| 已入库 | 记忆库已确认 | 跳转到该条目 |
| 失败 | 被拒，附原因类别 | 仅当失败可重试时才提供重试 |
| 未知 | 结果未知，请勿重复提交 | 跳转记忆库核对 |

未知状态绝不渲染成绿色，也绝不提供盲目重试。

### 记忆 diff 审核

当 provider 支持受审抽取时，卡片对每条内容提供接受、编辑、拒绝，编辑时保留原文可见。新账号默认开启审核，并按范围可配置。

### 步骤时间线

把现有的工具调用渲染扩展为一条时间线：每个模型步骤一行，含意图摘要、工具标签、耗时与 token 数。展开后显示工具参数与结果，可复制。回合结束后折叠为一行，最后失败的步骤保持展开。

### 子代理树

子代理嵌套在派生它的那一步下面，各自有状态。失败的子代理渲染其失败与部分产出，绝不消失。可见嵌套默认展开一层，每层提供展开控件。

### 审批卡

同一套组件服务文件写入、shell 命令与跨范围记忆操作。它说明变更内容、目标、范围，以及拒绝后的结果。破坏性操作渲染为阻塞式，可逆操作渲染为非阻塞式，并且始终显示被请求的是谁。

### 产物侧栏

本轮产生的文件、计划与交付物收集在侧栏，重新加载后仍在。新产物触发非模态提示，附打开动作。

## 记忆中心

同一份数据上的四个视图，共用范围切换器（工作区、全局）与时间筛选。

- **集合。** 每个集合一张卡片，含条目数、最近活动，以及区分关闭、未配置、不可用、为空的健康状态行。卡片主操作随状态变化：去配置、重试、浏览。
- **时间线。** 条目按时间排序、按项目分组。每条可展开到来源（哪一轮对话或哪次手工写入）、它支撑了哪些决策，以及修改历史。纠正会打开编辑器并追加一个版本。
- **图谱。** 仅在 provider 返回关系时渲染的力导向关系视图。它是次级标签页，绝不是落地视图；不可用时降级为普通列表并附提示。
- **进化。** 我的哪些记忆塑造了哪个执行体，以及若删除某条目哪些提案会失去证据。在此删除走标准的两步确认，并显示受影响的提案。

## 执行体中心

每个执行体一页，含五个区块：行为契约、能力表（工具、记忆范围、知识授权、审批策略）、执行记录、进化报告、版本。

- **执行记录**渲染为可筛选表格（结果、窗口、触发方式），详情抽屉把每个字段解析到对应的会话回合。
- **进化报告**渲染为一份文档：摘要指标、证据引用、逐项提案卡（含 diff、预期效果、影响半径、置信度）。页脚承载审批控件、审批人姓名，以及一句直白说明——这个决定属于用户。
- **版本**渲染为列表，每行提供启用与回滚，已生效版本显示其对照窗口结果。

报告状态到视觉状态的映射：已生成（中性）、审核中（强调色）、已批准（成功）、已拒绝（弱化并附理由）、已生效（成功并链接版本）、影子失败（警告，退回审核）。

## 执行体广场

发现、详情、安装、发布、治理。

- **发现**按要办的事分组，不按厂商。卡片显示执行体名称、任务短语、信任等级、一行能力摘要与记忆声明摘要。排序要说明依据什么排序；安装量绝不出现。
- **详情**先给行为契约，再给授权表（工具、为什么需要、能触碰什么）、记忆声明、审批策略、模型要求、成本区间、带 diff 的版本历史，以及只有真实会话才能发布的评价。
- **安装**展示相对用户现有名单的能力 diff，版本新增工具或记忆范围时必须显式确认；移除则无需确认即生效。
- **发布**是引导式流程：元数据、行为契约、授权、记忆声明、沙箱试运行结果、支持联系方式，最后是审核状态。
- **治理**把举报、下架、弃用作为一等标签页，每个详情页都有举报动作。

## 知识中心

层级切换（个人、组织、企业），然后是集合。每个集合页显示层级、维护者、共享状态、引用它的执行体，以及版本状态。

- **提升**是受审提案流程：选择目的地、声明脱敏、指定批准人、提交。界面要显示源条目仍留在原处。
- **共享**使用两个独立控件——可读人群与用途——每次放宽确认都以人数说明结果受众。
- **索引升级**渲染为维护作业，显示成本、耗时、受影响的查询，并在旧索引保留期间提供回滚按钮。
- **引用**在对话中渲染为独立卡片，含集合、层级、版本、生效日期，以及链接两个版本的过期标记。

## 视觉设计

### 令牌

所有颜色、间距、圆角与字体都来自 `--dsw-*` 令牌；组件不定义字面颜色。界面依赖的语义映射：

| 含义 | 令牌角色 |
|---|---|
| 成功（已入库、已生效） | 正向底色 + 正向前景 |
| 警告（降级、未知） | 警告底色 + 警告前景 |
| 危险（失败、破坏性） | 危险底色 + 危险前景 |
| 弱化（关闭、已拒绝、过期） | 抬升底色上的弱化前景 |
| 强调（审核中、主操作） | 品牌强调色 |

### 布局与密度

- 左栏 264px，右栏默认 360px、展开 480px；对话列自适应。
- 报告与详情页内容宽度上限 880px，左右留白 24px，使 diff 保持可读。
- 密度是一个设置项、两个取值；紧凑模式行高降到 32px，次要元数据收到悬停里。
- 小于 768px 时右栏转为全屏，左栏变抽屉，步骤时间线只保留摘要。表格型页面转为卡片列表。

### 交互规格

| 交互 | 规格 |
|---|---|
| 切换能力开关 | 先乐观更新，再以服务端权威状态覆盖；不一致时回退并给出内联解释 |
| 破坏性操作 | 两步确认，第二步点名具体对象；确认按钮绝不是默认焦点 |
| 长任务 | 进度卡显示已耗时，可取消时提供取消动作，完成时给出结果链接 |
| 加载 | 卡片布局用骨架屏，内联组件用不确定进度线；不使用整页转圈 |
| 空态 | 按状态命名原因，并给出一个主操作 |
| 错误 | 内联呈现，可重试的类别提供重试，其余给出可复制的诊断 id |
| 键盘 | `g h` 首页、`g m` 记忆、`g a` 执行体中心、`g p` 广场、`g k` 知识库；`?` 通过 `ui-shortcuts` 打开快捷键面板 |

### 无障碍与动效

每个控件都有可见焦点；状态绝不只靠颜色传达（每个状态同时带图标与文字）。动效遵循 `prefers-reduced-motion`；步骤时间线与广场卡片提供无过渡的减弱动效版本。

## 状态归属

| 数据 | 通道 |
|---|---|
| 会话派生数据（召回、写入、步骤、审批） | 基于会话投影的框架 hook |
| 跨面板界面状态（选中范围、筛选、打开的标签页） | 每页在 `apply` 中创建的一个声明式 store |
| 不绑定会话的服务端读取（记忆库、时间线、报告） | 通过 `useResource` 走 Remote 命名空间，并按页面缓存 |
| 瞬时本地状态（草稿、展开） | 组件状态 |

组件不手工订阅；不存在模块级句柄；绝不把服务端数据镜像进本地状态。编辑流程把草稿放在组件状态里，通过注入的回调提交。

## 文案与本地化

所有字符串位于 `packages/client/<pkg>/src/client/locales.ts`，中文词典是键集合的真相来源，英文是第二份词典。设计强制执行的文案规则：

- 状态文案说结果，不说机制：写“尚未保存——服务还没确认”，不写“状态：pending”。
- 未知结果绝不使用成功语汇。
- 审批控件点名到人：写“以 <用户> 身份批准”，不写“批准”。
- 英文文案统一使用句首大写（sentence case）。

## 性能预算

| 界面 | 预算 |
|---|---|
| 中心页首屏 | 参考机型上低于 400ms |
| 步骤时间线单行流式更新 | 每批低于 16ms |
| 记忆库翻页 | 命中缓存时每页低于 150ms |
| 报告页（500 条记录） | 低于 800ms，使用虚拟化 |
| 广场卡片 | 图片懒加载，单张低于 120KB |

长列表虚拟化；diff 超过 200 行时截断并提供展开；首屏以上的 Remote 读取在路由意图出现时预取。

## 测试

- 每个包针对状态映射与文案选择编写行为单测。
- 插槽组装测试：销毁 fiber 后断言贡献消失（仓库的 HMR 安全规则）。
- 无障碍检查覆盖焦点顺序、对比度令牌与减弱动效。
- 录屏要求：本计划中的每项 GUI 变更都附真实服务器录屏；产品设计的验收标准原样适用。

## 交付顺序

1. 对话内的信任界面（召回条、写入受理、状态词汇）。
2. 记忆中心的集合与时间线。
3. 带执行记录的执行体中心。
4. 进化报告的审核与审批。
5. 执行体广场的发现、详情、安装。
6. 知识中心，然后是提升与共享。
