# Project code guide

English | [中文](项目代码说明.zh.md)

## Summary

`dsh` (DeepSeek Harness) is an agent harness built on Cordis: plugins contribute services, typed events, and reversible effects to a shared context, and every product capability — the model adapter, the tool registry, the session log, the agent loop itself — is a plugin that can be replaced from configuration. There is no privileged core to patch.

This page is the map for reading the code tree. It states what each directory owns, how the archive is built, and where to start.

## Package groups

Packages live at `packages/<group>/<package>/`. The largest groups by package count:

| Group | Packages | Role |
|---|---|---|
| `client/` | 72 | Web UI plugins: primitives, conversation, memory, subagent, settings, and the rest |
| `experimental/` | 63 | Evaluated capabilities without a product-support commitment; experimental status is independent of delivery |
| `util/` | 23 | Zero-dependency utilities |
| `session/` | 22 | The append-only event log, persistence, format versions, checkpoints, and query |
| `shell/`, `core/`, `api/` | 10 each | Command execution; the product API spine (agent, loop, session, prompts, tools); the remote BFF and RPC gateway |
| `subagent/`, `llm/`, `host/` | 9 each | Delegated agents; model providers; the GUI host |
| `fs/`, `test-support/` | 8 each | Filesystem seam and tools; test infrastructure |
| `memory/` | 5 | The long-term memory seam, its MemoryBear provider, autosave, model-facing tools, and in-session agent creation |
| `bundle/` | 6 | Distribution layers: `base`, `web-app`, `headless`, `sdk-app`, `sdk-minimal`, `acp-app` |

Every package belongs to exactly one group; the group README is the authoritative package map for its family.

## How a running process is built

A running `dsh` is a plugin tree composed at boot from ordered layers: a **profile** (a named composition stored in the Harness home) names the bundles it stacks; each **bundle** carries Cordis config rows; then the user's `cordis.patch.yml`, then `--patch` overlays apply. A patch targets a row by id, replaces its whole config, or inserts new rows.

```sh
dsh --profile web --dump-config   # print the tree this machine boots
```

The shipped profiles are `web`, `headless`, `sdk`, `sdk-minimal`, and `acp`. Only named profiles launch supported Node applications; package bins and ad-hoc in-process mounting are rejected by `verify-application-entrypoints`.

## The core idea in one paragraph

A **Session** is an append-only log of typed events, and it is the single source of truth: anything that reaches a model request must be reconstructable from the log (the `model-visible ⟺ logged` rule). The **agent loop** claims input, snapshots model selection, assembles prompt sections and tool schemas, streams the request, runs tools, and closes the turn. Each **capability seam** — memory, filesystem, shell, LLM, sandbox, knowledge — has three roles: a Service Definition, one or more providers, and consumers. Registrations are effects that unwind when their plugin unloads.

## Working in the tree

| Need | Command |
|---|---|
| Install | `pnpm install` (pnpm workspaces, Node ≥ 24.9) |
| Build artifacts | `pnpm run build:artifacts` |
| Type-check the aggregate | `pnpm run build:check` |
| Unit tests | `pnpm run test` |
| Coverage gate | `pnpm run test:coverage` (per-file 100% on `packages/*/*/src`) |
| Documentation gates | `pnpm run doc-sync` |
| Run from source | `pnpm dsh --profile web` (needs `DEEPSEEK_API_KEY`) |

Read [`AGENTS.md`](../代码文件/AGENTS.md) before changing `packages/`, and [`docs/architecture.md`](../代码文件/docs/architecture.md) for the full architecture.
