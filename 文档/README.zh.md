# 文档索引

[English](README.md) | 中文

## 概要

本目录存放**可以脱离代码仓库阅读**的产品与设计文档：某个产品界面背后的推演、它否决了哪些方案、以及它必须满足的验收标准。它刻意与代码树分离，也与 `docs/` 分离——后者随仓库发布，描述的是"当前已经存在的东西"。

## 目录内容

| 文档 | 覆盖内容 |
|---|---|
| [面向 C 端的记忆与执行体产品界面](2026-11-18-consumer-memory-agent-product-design.md) | 记忆、执行体、执行体广场、记忆驱动的进化、执行记录与进化报告、知识库：页面结构、功能设计、状态模型、交付顺序、验收标准与风险 |
| [项目代码说明](项目代码说明.md) | `dsh` 代码树是什么、每个顶层目录负责什么、包如何分组、一个运行中的进程如何装配、以及如何在树里工作 |
| [前端开发文档](前端开发文档.md) | 可施工的 Web 客户端工作：包、插槽、store、页面清单、对话界面、状态归属、视觉设计、交互规格、性能预算 |
| [后端开发文档](后端开发文档.md) | 可施工的 Host 工作：能力接缝、Remote 命名空间、持久事件、执行记录、进化报告流水线、权限与租户、provider 接入 |

每份文档都有英文页与中文页，并在旁边配一份 `.i18n.yaml` 一致性记录。两侧要一起改并重新记录配对；记录的格式归仓库的 `verify-translation-pairing` 闸门所有。

## 三层文档的分工

| 层 | 位置 | 是什么 |
|---|---|---|
| 产品设计 | 本目录（`文档/`） | 可能尚未实现的提案与设计；脱离代码即可阅读 |
| 仓库文档 | [`docs/`](../代码文件/docs/architecture.md) | 当前状态文档，随仓库与文档站点发布 |
| 决策记录 | [`.agents/notes/`](../.agents/notes/README.md) | 与代码绑定的设计决策，按固定格式与 proposed/implemented/rejected 生命周期管理 |

当一份文档需要作为**仓库决策**被闸门扫描和评审、而不只是产品提案时，它会从本目录迁入 `.agents/notes/proposed/feature/`。

## 维护备注

本目录的文档不受 Agent Note 格式闸门扫描，那个闸门只作用于 `.agents/notes/` 树；但它们仍受双语配对闸门扫描，因为该闸门覆盖仓库里的每一个 Markdown 页面。
